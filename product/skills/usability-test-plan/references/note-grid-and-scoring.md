# Note-taking grid and scoring

## Roles

- **Moderator** runs the session and talks. Doesn't take notes beyond a quick mark.
- **Note-taker** fills the grid live and runs the timer. Doesn't talk to the participant.
- **Observers** watch silently with cameras and mics off, and send any question to the moderator in a private message. The moderator decides whether to ask it in the debrief.

## The grid

One sheet per study, one row per participant per task. Use P1, P2… never names.

| P | Task | Outcome | Time | Path taken | Hesitations and wrong turns | What they said | Help given | Problem and severity |
|---|---|---|---|---|---|---|---|---|
| P1 | T1 | | | | | | | |

- **Outcome:** one of the four levels below.
- **Time:** from the agreed start to the agreed end. Leave blank for think-aloud tasks.
- **Path taken:** the screens in order, briefly.
- **Hesitations and wrong turns:** where they paused more than a few seconds, tapped the wrong thing, went back.
- **What they said:** short, close to their words. Mark exact quotes with quotation marks only if they're exact.
- **Help given:** the exact prompt the moderator used, if any, and when. Any task with a hint beyond a neutral prompt can't score better than "major issue".
- **Problem and severity:** what went wrong, in one line, and a severity from the scale below.

Add one row per participant for the comprehension check and one for debrief answers.

## Outcome levels

Score each task on four levels. Count how many people land at each level and report it in words ("3 of 5 passed, 1 with a minor issue, 1 failed"). Don't turn the levels into numbers and average them: they're ordered categories, not measurements.

| Level | Means |
|---|---|
| **Pass** | Reached the end state without help, inside any time target |
| **Minor issue** | Reached the end state without help, but hesitated, took a wrong turn and recovered, or went over the time target |
| **Major issue** | Reached the end state only after a hint beyond a neutral prompt, or ended in a state they didn't intend without noticing |
| **Fail** | Didn't reach the end state, gave up, or the moderator moved on |

"Without help" in a target (for example "4 of 5 without help") counts **pass** and **minor issue** only, unless the time target is part of the criterion; then it counts **pass** only.

## Severity

| Severity | Means |
|---|---|
| **Blocker** | Stops people completing the task, or leads to a wrong result they don't notice |
| **Major** | Causes real delay or a wrong turn for several people |
| **Minor** | Slows one or two people briefly |
| **Cosmetic** | Noticed, didn't affect the task |

A problem's severity goes up when more people hit it. Log every problem once, with the participants who hit it.

## Timings

- Time only the tasks with a time target, and run those without think-aloud, because narrating slows people down. Ask them to talk it through straight afterwards.
- Report the **median** of five times, and each time individually. With five people the median is the third value in order.
- A built-in timer in the prototype beats a stopwatch. Note whether any time includes a moderator interruption.

## Turning the grid into a decision

1. For each task, count the outcome levels and compare with its target.
2. For each research question, write one line on what the grid shows, with participant IDs.
3. List problems by severity, then by how many people hit them.
4. Apply the plan's pass, iterate or stop rule. Don't change the rule after seeing the results; if you think it was wrong, say so separately.
5. Remember the limits. Five people find problems; they don't produce a rate you can generalise. Report counts, not percentages.
