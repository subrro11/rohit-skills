# Showcase: Shiftplate pilot launch plan

A launch plan for a fictional product. Shiftplate is the meal-planning app for nurses on rotating 12-hour shifts from the [PRD Generator showcase](../../../prd-generator/examples/shiftplate/). By this point it has a PRD, a [research pass](../../../deep-research/examples/shiftplate/) that changed the use-by default to 3 days, copy and UX reviews, a 5-nurse usability test, and an experiment design for a one-tap check-in. This plan launches the 20-nurse, 4-week pilot. It's a plan, so it holds thresholds and owners, not results.

[Read the plan](LAUNCH-PLAN.md)

Moments worth looking at:

- **Small but sensitive sets the tier.** Twenty people is low reach, but food safety and rota data are high risk, so it's tier 2: strict rollback, careful consent, no press.
- **It catches three conflicts with the PRD** (one hospital, not several; a 3-day default, not 4; 4 weeks, not 4–6) and makes updating the PRD a no-go item instead of picking quietly.
- **Harm triggers have a threshold of one.** A single portion planned past its use-by pauses re-plan within an hour, and the pause message is already written.
- **Support hours fit the users.** Nurses work nights, so food-safety and data issues get an answer at any hour during the first wave.
- **It protects the experiment.** No nudges to check in, the flag can't change mid-pilot, and both waves contain both arms.
- **The review applies the PRD's rule as written**, with leavers counted as not passing, and a wider beta only gets planned if the pilot passes.
