# Further reading

Public guidance that agrees with, and goes deeper than, the rules in this skill. The rules are written in this skill's own words; these pages are where to read more.

| Source | What it covers |
|---|---|
| [Error-Message Guidelines](https://www.nngroup.com/articles/error-message-guidelines/), Nielsen Norman Group | Where errors go, how to word them, keeping input, no blame |
| [Designing Empty States in Complex Applications](https://www.nngroup.com/articles/empty-state-interface-design/), Nielsen Norman Group | Empty states that show status, teach and offer the action |
| [Confirmation Dialogs Can Prevent User Errors](https://www.nngroup.com/articles/confirmation-dialog/), Nielsen Norman Group | When to confirm, naming the object, outcome verbs on buttons |
| [Error message](https://design-system.service.gov.uk/components/error-message/), GOV.UK Design System | One message per problem, reusing the label's words, words to avoid |
| [A to Z style guide](https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/style-guides/a-to-z-style-guide/), GOV.UK | Sentence case, dates, numbers, abbreviations, plain English |
| [Voice and Tone](https://styleguide.mailchimp.com/voice-and-tone/), Mailchimp Content Style Guide | A steady voice with a tone that follows the reader's state |
| [Capitalization](https://learn.microsoft.com/en-us/style-guide/capitalization), Microsoft Writing Style Guide | Sentence-style capitalisation for headings and UI labels |
