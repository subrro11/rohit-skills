# Sources

Public guidance the references draw on. Each was opened and read when the skill was written; the references put it in their own words. Re-check the page before citing a specific figure in a review.

| Source | What it's used for |
|---|---|
| [10 Usability Heuristics for User Interface Design](https://www.nngroup.com/articles/ten-usability-heuristics/), Jakob Nielsen, Nielsen Norman Group | The ten heuristics in `heuristics.md` |
| [Severity Ratings for Usability Problems](https://www.nngroup.com/articles/how-to-rate-the-severity-of-usability-problems/), Jakob Nielsen, Nielsen Norman Group | Frequency, impact and persistence, and the 0–4 scale behind `severity-and-format.md` |
| [Touch Targets on Touchscreens](https://www.nngroup.com/articles/touch-target-size/), Aurora Harley, Nielsen Norman Group | The physical size guide (about 1 cm square) and why small targets slow people down |
| [Designing Empty States in Complex Applications: 3 Guidelines](https://www.nngroup.com/articles/empty-state-interface-design/), Kate Kaplan, Nielsen Norman Group | Empty states as status, learning cue and a way forward, in `states-checklist.md` |
| [Understanding SC 2.5.8: Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), W3C | The 24 × 24 CSS px minimum, its spacing exception, and the 44 × 44 enhanced level (2.5.5) |
| [Understanding SC 1.4.3: Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), W3C | 4.5:1 for body text, 3:1 for large text |
| [Understanding SC 2.4.7: Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html), W3C | A visible keyboard focus indicator |

Platform guidance from Apple (Human Interface Guidelines) and Google (Material Design, Android accessibility help) also sets touch-target minimums. Those pages didn't load for reading when this skill was written, so no figures are quoted from them here. Read them directly before relying on them.
